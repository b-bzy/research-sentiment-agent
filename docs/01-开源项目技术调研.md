# 开源项目技术调研：研报多空判断

> 采集时间：2026-09-10 ｜ 数据源：GitHub Search API（`gh search repos` / `gh repo view`）
> Star 数为采集当日快照，仅用于判断项目活跃度量级

---

## 〇、调研口径（先框定范围）

**本项目要实现的唯一功能：**

> 把从各家期货公司拿到的研报，判断成**看多 / 看空 / 中性**，汇总成「全市场当前偏多还是偏空」，并且这个数按时间可比。

因此本次调研只回答三个问题：

| # | 问题 | 对应链路 |
|---|---|---|
| 1 | 一篇研报怎么判成多/空/中性？ | **文本 → 多空标签** |
| 2 | 多篇怎么汇总成一个市场结论？ | **多空标签 → 市场净值** |
| 3 | 这个数怎么保证不同时间可比？ | **口径与时点** |

**明确排除在外**（与「研报判多空」无关，本次不展开）：

- ❌ 量价类市场情绪指数（波动率、成交、涨跌停、广度加权）—— 情绪来自行情不来自研报，是另一条路线
- ❌ 多 Agent 交易决策框架 —— 做的是买卖决策，不是研报观点判读
- ❌ 调查/持仓类情绪（AAII、COT、NAAIM）—— 数据源完全不同
- ❌ 金融大模型训练与评测基准 —— 本项目不训模型底座

---

## 一、核心结论

| # | 结论 |
|---|---|
| 1 | **GitHub 上没有同形态项目。** 「研报 → 多空判断 → 全市场汇总」的完整实现搜不到；`研报 stars:>50`、`research report sentiment` 两条检索式的有效返回几乎为 0 |
| 2 | **只有第 1 步（文本 → 多空标签）有成熟轮子可用**，第 2、3 步基本要自研 |
| 3 | 第 1 步最贴近的开源资产是 **`finbert-tone`**——它的训练语料就是分析师研报，标注方式就是**句级三分类**，跟本项目的任务定义完全一致 |
| 4 | 中文侧没有对应的研报情绪模型，但有**现成的中文金融情感词典**可作为关键词表起点 |
| 5 | 研报判多空有四个已知的坑，都跟「一篇研报里观点不止一个」和「分析师不轻易喊空」有关（见第三节） |

## 二、第 1 步：文本 → 多空标签

金融文本判多空有三条路线，**词典 / 微调模型 / LLM**，生产中通常并存：词典负责可解释与兜底，模型负责批量稳定，LLM 负责长句与新表述。

| 项目 | Star | 路线 | 对本项目的价值 |
|---|---:|---|---|
| [yya518/FinBERT](https://github.com/yya518/finbert) | ≈660 | 在 10-K/10-Q(2.5B) + 电话会(1.3B) + **分析师研报(1.1B)** 共 4.9B token 上预训练；`finbert-tone` 用 **1 万条人工标注的分析师研报句子**做三分类微调 | ⭐ **最直接的方法论对标**：语料是研报、标注单位是句子、输出是正/负/中性三分类。证明「研报句级多空」是可标注、可学习的任务 |
| [ProsusAI/finBERT](https://github.com/ProsusAI/finBERT) | ≈2.2k | BERT 在 Financial PhraseBank 上微调，三分类 | 英文金融情绪的事实标准 baseline |
| [MengLingchao/Chinese_financial_sentiment_dictionary](https://github.com/MengLingchao/Chinese_financial_sentiment_dictionary) | ≈226 | 中文金融情感词典 9228 词（消极 5890 / 积极 3338）。构建法：LM 英文金融词典汉化 + 通用中文词典金融语境筛选 + word2vec 扩充 | ⭐ 中文关键词表的现成起点，可直接叠加期货词表（升贴水、仓单、逢低偏多…） |
| [DavionWu2018/Sentiment_dictionary](https://github.com/DavionWu2018/Sentiment_dictionary) | ≈164 | 词典打包：正式文本 + 股吧社媒两套金融词典，**外加停用词、程度副词、否定词表** | ⭐ 程度副词与否定词是关键词法绕不开的坑（「**不**看好」「**略**偏空」「**暂不**看空」），此仓提供现成资源 |
| [dongyuanxin/news-emotion](https://github.com/dongyuanxin/news-emotion) | ≈355 | 中文金融文本情感分析模型 | 中文侧可跑通的完整小样例 |
| [KVignesh122/AssetNewsSentimentAnalyzer](https://github.com/KVignesh122/AssetNewsSentimentAnalyzer) | ≈198 | 直接用 GPT 给资产新闻打情绪分的 pip 包 | LLM 路线的最小实现，适合做人工标注的对照组 |

**技术判断：**

1. **纯词典法在研报场景有明确天花板。** 研报的多空判断依赖句式而非词汇——「短期承压，中期仍有支撑」逐词统计会被打成中性。但词典仍必须保留，因为交易员会追问「凭什么说它偏空」，关键词是唯一能直接举证的形式。
2. **句级切分 → 句级判断 → 篇级汇总，比整篇打一个分更稳。** 这是 `finbert-tone` 的做法，也是后文华泰研报的做法。原因见第三节第 2 条。
3. **本项目「关键词提取 + 打分模型」的组合是合理的。** 关键词管可解释与可审计，模型管泛化。

## 三、第 1 步的四个坑（都跟研报文体有关）

### 3.1 一篇研报里的观点不止一个 → 整篇打分会被抹平

RavenPack 官方文档明确承认：其情绪模型不区分不同观点视角，**一段文本内若有对立观点，结果要么被打成中性，要么被主导观点吞掉**。

期货研报的典型结构就是「多品种 + 多周期」：一篇里同时讲沪铜、螺纹、焦煤，且常见「短期偏空、中期偏多」。

→ **必须先按品种/周期切分，再逐段判多空，最后才汇总。** 这是整条链路上最不能省的一步。

### 3.2 分析师不轻易喊空 → 正负等权会让指标长期漂在偏多区

中文金融情感词典里消极词 5890、积极词 3338，而**分析师研报本身正面表述占绝对多数**。华泰的解法是构建调整因子时**给负面文本更大权重**——在一片看多的语境里，一句看空的信息量远大于一句看多。

期货研报同样有这个惯性：「暂不看空」「谨慎追空」「前多保护利润」都是变相的偏多或中性表达。

→ **非对称加权应当是打分模型的显式设计项，不是调参细节。**

### 3.3 情绪判断可能被「研报数量」解释掉

华泰的实测结论：原始情感因子表现好，但对「研报评分因子」和「研报数量因子」做中性化后，**残差表现最差**——说明它的大部分信息其实能被"有多少家在写、给了什么评级"解释。只有做了负面加权的调整因子，残差才保持表现。

→ **评测时必须回答：我的多空分数，相比单纯"数一下多少家看多、多少家看空"，增量在哪里？** 这是产品答辩和技术评审都会追问的问题，也是这个项目是否成立的分水岭。

### 3.4 用错时点会引入未来函数

华泰研报明确指出：研报文本有 `CREATE_DATE`（撰写）和 `INTO_DATE`（入库）两个时间，**文本只有在进入数据库之后才是可用的**。

→ **所有历史指标必须以入库时点计算。** 用撰写时点做回测，指标会凭空获得未来信息，结果全部失真。

## 四、第 2、3 步：汇总与可比 —— 开源基本空白

搜遍 GitHub，「多篇文本的多空标签 → 一个市场净值 → 时间序列」这一段没有可复用实现。相关的只有：

| 参考 | 说明 |
|---|---|
| [IndexMundi Commodity Sentiment](https://www.indexmundi.com/commodities/sentiment/) 的公式 | **净得分 =（看多数 − 看空数）÷ 总数 × 100**，+100 全体看多，−100 全体看空。⭐ 最简 baseline，本项目的复杂模型必须能跑赢它，否则复杂度没换来价值 |
| 华泰研报的聚合口径 | 句级得分 → 篇内取均值 → 同标的当日多篇取均值 → 过去 90 自然日**线性衰减加权求和**（越近权重越大） |
| [Quantify-hp/Market-sentiment-index](https://github.com/Quantify-hp/Market-sentiment-index) 的缺失值处理 | 各分项统一归一到 0–100，**数据缺失时用 50 分中性值兜底**。可用于研报无覆盖的日子 |

**技术判断：** 第 2、3 步是本项目真正的自研部分，也是产品价值所在。它们不难在算法，难在**口径定义要经得起追问**：多少家算"全市场"？一家发三篇算三票还是一票？观点跨周期时按哪个周期归档？

## 五、配套环节（只列必要的，不展开）

| 环节 | 结论 |
|---|---|
| 研报抓取 | **无成熟轮子。** 相关仓库只有 [lzhttn/EastmoneyCrawler](https://github.com/lzhttn/EastmoneyCrawler)（≈22 star，东方财富研报 PDF 下载）等零星项目，均为个人小仓。多来源多格式研报的统一入库确实要自己啃 |
| PDF 解析 | 直接用 [opendatalab/MinerU](https://github.com/opendatalab/MinerU)（≈79.6k star），把 PDF 转成带标题层级的 Markdown/JSON。**不建议自研**——解析质量直接决定上限，把「沪铜」章节的观点错切到「沪铝」名下，后面再准也没用 |
| 推送 | 企业微信/飞书机器人即可，无技术难点 |
