## 三、缺陷清单

### P0 · 方向判反类（打分引擎）

这一类的共同后果：**把看空的研报判成看多，或反之**。指标不会报错，只会悄悄变错。

---

#### BUG-01 · 品种名里的「不」被当成否定词，整块判反

**文件** `sentiment/score.py` ｜ **用例** TC-SCORE-03

```python
from sentiment.score import classify_advice as C
C('不锈钢逢高沽空')       # → +0.5  应为 -1.0
C('不锈钢空头思路为主')     # → +0.5  应为 -2.0
C('不锈钢建议做空')        # → +0.5  应为 -2.0
C('不锈钢逢低偏多')        # → -0.5  应为 +1.0
```

实际输出全部带 `negated=True, conf=0.55`。

**根因**：通用否定层在方向词左侧窗口里找否定词，「不锈钢」的「不」命中了 `NEGATIONS` 表。

**影响**：不锈钢（SS）是品种词典内的正式品种。**该品种的所有方向判断全部反向**。

---

#### BUG-02 · 否定词表缺口：并非 / 并未 / 没有 / 未必 完全不生效

**文件** `sentiment/score.py` ｜ **用例** TC-SCORE-04

```python
C('并非看空')           # → -1.0  应为 >0
C('未必看多')           # → +1.0  应为 <0
C('没有空头思路为主')      # → -2.0  应为 >0
C('并未看多')           # → +1.0  应为 <0
```

`negated=False`——这些词根本不在否定词表里。

**根因**：`NEGATIONS` 只收了 `不/勿/莫/无需/不宜/暂不/不要/难以`，漏掉书面语常用的否定式。

**影响**：**满强度反向**（±1.0、±2.0），不是降级为中性，比 BUG-01 更严重。

---

#### BUG-03 · 否定回看窗口过短，否定词与方向词一隔开就漏

**文件** `sentiment/score.py` ｜ **用例** TC-SCORE-05

```python
C('不建议做多')                  # → -0.5  ✓ 正确
C('不建议在当前位置做多')            # → +1.0  ✗ 判反
C('不建议在当前这个位置轻易做多')       # → +1.0  ✗ 判反
```

**根因**：否定回看窗口只有 6 个字，插入状语就超窗。

**影响**：研报里「不建议在当前位置追多」这类写法极常见。

---

#### BUG-04 · 标点缺失导致符号翻转

**文件** `sentiment/score.py` ｜ **用例** TC-SCORE-06

```python
C('不确定性上升，逢高沽空')     # → -1.0  ✓
C('不确定性上升逢高沽空')       # → +0.5  ✗ 符号翻转
C('不排除回调，逢低偏多')       # → +1.0  ✓
C('不排除回调逢低偏多')        # → -0.5  ✗ 符号翻转
```

**根因**：引擎靠标点切子句；没有标点时「不确定性」「不排除」里的「不」被误挂到后面的方向词上。

**影响**：**同一句话加不加逗号，结论相反。** 研报排版不规范时会大面积踩中。

---

#### BUG-05 · 一句里两个对立方向词时按规则表顺序裁决 → 系统性偏多

**文件** `sentiment/score.py` ｜ **用例** TC-SCORE-07

```python
C('偏空思路逢低偏多')    # → +1.0
C('偏多思路逢高沽空')    # → +1.0    ← 两句方向相反，结论都是「多」
```

**根因**：多个规则命中时按**规则表定义顺序**返回第一个，而不是按**文本位置**裁决，也不识别冲突。

**影响**：这不是随机误差，而是**系统性偏多**——正好放大了「分析师不轻易喊空」的正面偏斜。

---

#### BUG-06 · 文末【风险提示】的「操作建议：」劫持上一个品种的方向

**文件** `sentiment/segment.py` ｜ **用例** TC-SEG-11 / TC-DATA-02

```python
from sentiment.segment import split_segments
t = """【黑色】螺纹钢
逻辑分析：需求回暖。
操作建议：逢低偏多。

【风险提示】
本报告基于公开资料，不保证准确性。
操作建议：请投资者谨慎决策，逢高沽空需自担风险。
"""
split_segments(2, t)
# → 只切出 1 块：product=RB，advice='请投资者谨慎决策，逢高沽空需自担风险。'
```

**根因**：`【风险提示】` 不含品种 → 不产生新块 → 其内容被并进上一个品种块；`advice_text` 抽取取"最后一个建议标签"，于是免责声明覆盖了真实建议。

**影响**：**螺纹钢的真实建议「逢低偏多」被免责声明的「逢高沽空」取代，方向从 +1.0 翻成 −1.0。**
几乎所有券商研报都有免责声明，这条在真实数据上是必踩。

---

#### BUG-07 · 编号 / Markdown 标题文档里品种块整体丢失

**文件** `sentiment/segment.py` ｜ **用例** TC-SEG-09 / TC-SEG-10

```python
t = """# 商品日报

## 一、市场综述
昨日沪铜主力震荡走强，库存持续去化。
操作建议：逢低偏多。
"""
split_segments(1, t)
# → 1 块，product_code=None（宏观块）
```

沪铜的票**消失了**，被算进大盘的宏观票。

**根因**：切分只认 `【品种】` 这种粗切锚点；标题不含品种时，正文里的品种不参与归属判定。

**影响**：不用【】格式的机构，其研报的品种票会全部丢失。

---

#### BUG-08 · 非法文件名日期 → `ingest_time` 退回真实当前时间，垃圾数据混进「今天」

**文件** `sentiment/ingest.py` ｜ **用例** TC-DATA-04

```bash
cp data/inbox/20260910_永安期货_商品期货日报.txt "data/inbox/20261340_测试机构_非法日期.txt"
python3 run.py reset && python3 run.py ingest
```

实际落库：

```
(org_id=11, publish_time='', ingest_time='2026-09-10T23:23:39', title='非法日期')
```

**根因**：demo 回填模式解析日期失败后 fallback 到 `now()`，且没有任何告警。

**影响**：一个文件名写错的垃圾件会**凭空造出一家机构**（`coverage_count` +1）并把票投进执行当天的大盘指标。

---

#### BUG-09 · 整日数据消失后，旧指标残留在 `daily_index`

**文件** `sentiment/aggregate.py` ｜ **用例** TC-AGG-08

```bash
# 删掉 09-08 的全部研报与观点块后重新聚合
python3 -c "...delete from report where ingest_time like '2026-09-08%'..."
python3 run.py pipeline
# → daily_index 里 09-08 依然存在
```

**根因**：重算按「有数据的日期」循环，某天彻底没数据时该天不进循环，旧行永远不会被清掉。

**影响**：数据回溯、口径修正、误入库清理这些场景下，指标会停留在过时值上。

### P1 · 功能缺陷

#### BUG-10 · 转折 / 条件从句被前半句劫走

**文件** `sentiment/score.py` ｜ **用例** TC-SCORE-08 / TC-SCORE-09

```python
C('虽然基本面偏多，但操作上建议做空')            # → +1.0   应 <0
C('前期多头思路为主，但目前已转为空头思路为主')      # → +2.0   应 <0
C('如果宏观转弱可做空，当前建议逢低偏多')          # → -1.0   应 >0
C('一旦破位则偏空，当前观望为主')               # → -1.0   应 = 0
```

**根因**：逐子句扫描「第一个命中的子句说了算」，不识别 `虽然…但`、`如果…则`、`前期…目前` 这类结构。
研报的真实主张恰恰在**转折后**、**条件句外**。

---

#### BUG-11 · 双重否定含表外否定词时判反

**文件** `sentiment/score.py` ｜ **用例** TC-SCORE-10

```python
C('不能不看多')    # → +1.0  ✓
C('并非不看多')    # → -0.5  ✗
C('无法不看空')    # → +0.5  ✗
```

BUG-02 的衍生问题：外层否定词不在表内，只反转了内层。

---

#### BUG-12 · 并发执行 `pipeline` 导致观点块翻倍

**文件** `sentiment/segment.py` / `sentiment/db.py` ｜ **用例** TC-PIPE-12

```bash
python3 run.py reset && python3 run.py ingest
(python3 run.py pipeline & python3 run.py pipeline & wait)
# segment 表：454 行（正常 227）
```

两个进程都读到「未切分」状态，各切一遍。无报错、无锁冲突。

**影响**：库里多出 227 条重复观点块。**指标本身未受影响**——「一家一票」去重把它吸收了
（大盘仍是 48/23/10，与正常一致）。属于数据完整性问题，不是指标正确性问题。

## 七、建议修复顺序（未执行）

| 顺序 | 缺陷 | 理由 |
|---|---|---|
| 1 | BUG-06 免责声明劫持 | 真实研报 100% 命中，且直接翻转方向 |
| 2 | BUG-02 否定词表缺口 | 满强度反向，改动成本最低（补表即可） |
| 3 | BUG-01 品种名含「不」 | 影响词典内正式品种的全部判断 |
| 4 | BUG-05 对立方向词系统性偏多 | 系统性偏差，会放大正面偏斜 |
| 5 | BUG-03 / BUG-04 否定窗口与标点 | 同属否定层，建议一起重构 |
| 6 | BUG-07 编号标题品种丢失 | 影响特定格式的机构 |
| 7 | BUG-08 / BUG-09 采集与聚合 | 影响数据完整性，不影响当前结论 |
| 8 | BUG-10 / BUG-11 从句与双重否定 | 需要句法分析，成本高，可留给 LLM 兜底层 |
| 9 | BUG-12 / BUG-13 | 并发与脚本，不影响单机演示 |

### 一条方法论建议

BUG-10（转折从句）、BUG-11（双重否定）这类问题，**用规则去堆是堆不完的**——
这正是 [03-架构方案.md](03-架构方案.md) 第五节「三层漏斗」里 LLM 层存在的理由。
demo 只做了第一层，所以规则的边界就是系统的边界。

修复时更值得做的，是**给规则层加一个「拿不准就降置信度」的机制**，
把这类复杂句式主动推给 LLM 层或人工复核队列，而不是硬判一个方向。
现在的问题不在于规则判错了，而在于**它判错的时候还给了 0.8 的置信度**。
