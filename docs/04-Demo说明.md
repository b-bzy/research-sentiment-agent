# Demo：期货研报多空打分 Agent

按 [03-架构方案.md](03-架构方案.md) 落地的**可运行演示版**。

> **零第三方依赖**，不用 `pip install` 任何东西。Python 3.10+ 直接跑。

```bash
# 在仓库根目录
python3 run.py demo
```

约 0.2 秒跑完全链路，终端出情绪日报，同时导出一个自包含 HTML 看板。

---

## 一、这个 demo 做了什么

**唯一功能**：把各家期货公司的研报判成看多/看空/中性 → 汇总成「全市场偏多还是偏空」→ 按时间可比。

实测基线（自带样本数据）：

```
① 采集   新入库 27 篇 ｜ MD5 重复跳过 0 篇 ｜ 失败 0 篇
③ 解析   解析成功 27 / 27 篇
④ 切分   切出 227 个观点块（品种 220 / 宏观综述 7 / 多品种合并 2）｜ 来自 27 篇研报
⑤ 打分   打分 227 / 227 块 ｜ 规则命中率（本样本集）99.6% ｜ 多/空/中 116/66/45 ｜ 低置信度待复核 9 条
⑥ 聚合   3 个交易日 ｜ 写入 111 行日度指标（无覆盖的品种不产出记录）
⑦ 呈现   推送文案 / 终端看板 / HTML 看板
```

产出的盘前推送文案：

```
📊 大盘情绪 65.5 分（偏多）｜较昨日 +2.8｜覆盖 10 家机构 / 81 个观点

板块  贵金属 +100  有色 +71  黑色 +96  能化 -68  油脂油料 -29  农产品 -29

变化最大  螺纹钢 -20 → +100（5 家转多）
分歧最大  原油（3 家看多 / 5 家看空）

对照 baseline（一家一票只数家数 8/1/1）85.0 分 ｜ 本模型 65.5 分
口径 netscore-v1 ｜ 打分 rule-v1 ｜ 多空中 48/23/10（30 个品种有覆盖，其余记 NA 不记 0）
```

## 二、链路与文件对照

```
① 采集 → ② 落地 → ③ 解析 → ④ 切分 → ⑤ 打分 → ⑥ 聚合 → ⑦ 呈现
```

| 环节 | 文件 | 职责 |
|---|---|---|
| ① 采集 | `sentiment/ingest.py` | 扫 `data/inbox/`、MD5 去重、解析文件名元数据、两个时间戳 |
| ② 落地 | `sentiment/db.py` | SQLite，5 张表（org / report / segment / score / daily_index） |
| ③ 解析 | `sentiment/parse.py` | txt/md 直通；html 极简抽正文；pdf 留适配位 |
| ④ 切分 | `sentiment/segment.py` | **全链路最关键**：标题层级 + 品种词典双重锚定 |
| ⑤ 打分 | `sentiment/score.py` | 规则引擎：特例表 → 常规表 → 否定反转 → 程度副词 |
| ⑥ 聚合 | `sentiment/aggregate.py` | 观点块 → 品种 → 板块 → 大盘，净得分公式 |
| ⑦ 呈现 | `sentiment/report.py` | 推送文案 / 终端富文本 / 单文件 HTML 看板 |
| 词典 | `sentiment/products.py` | 45 个商品期货品种（代码 + 别名 + 板块） |

### CLI

| 命令 | 作用 |
|---|---|
| `python3 run.py demo` | 一键：reset → 全链路 → 终端渲染 → 导出 HTML |
| `python3 run.py ingest` | 只跑采集 |
| `python3 run.py pipeline` | 解析 + 切分 + 打分 + 聚合 |
| `python3 run.py show [--date D]` | 终端情绪日报 |
| `python3 run.py push [--date D]` | 打印推送文案 |
| `python3 run.py html [--date D]` | 导出 HTML 看板 |
| `python3 run.py reset` | 清库重来 |

## 三、打分刻度

| 方向 | 典型表述 |
|---|---|
| +2.0 强烈看多 | 多头思路为主 / 坚定做多 / 建议做多 |
| +1.0 看多 | 逢低偏多 / 逢低做多 / 偏多思路 |
| +0.5 谨慎偏多 | 前多持有 / 前多保护利润 / **暂不看空** / **谨慎追空** |
| 0.0 中性 | 区间操作 / 短差操作 / 观望为主 / 高抛低吸 |
| −0.5 谨慎偏空 | 前空持有 / **暂不看多** / **不宜追高** |
| −1.0 看空 | 逢高沽空 / 逢高做空 / 偏空思路 |
| −2.0 强烈看空 | 空头思路为主 / 坚定做空 |

### ⚠️ 最容易判反的地方

粗体的四个是**期货研报特有的坑**，字面看是「空」，实际意思是「多」（反之亦然）：

| 表述 | 字面 | 真实含义 | 本项目判定 |
|---|---|---|---|
| 谨慎**追空** | 像看空 | 别去追空 → 偏多 | **+0.5** |
| 暂不**看空** | 像看空 | 暂时不看空 → 偏多 | **+0.5** |
| 不宜**追高** | 像看多 | 别去追多 → 偏空 | **−0.5** |
| 暂不**看多** | 像看多 | 暂时不看多 → 偏空 | **−0.5** |

处理办法：**特例表优先于通用否定逻辑**。若先跑「否定词 + 方向词 → 反转」的通用规则，
「暂不看空」会被拆成「不 + 看空」反转成中性，丢掉它真实的偏多含义。

`tests/test_score.py` 里 69 个用例把这些逐条锁死。

## 四、口径（这部分决定指标能不能用）

| 口径 | 说明 | 为什么 |
|---|---|---|
| **两个时间戳** | 存 `publish_time` 和 `ingest_time`，**所有指标一律用 `ingest_time`** | 周五发的报告周一才抓到，按发布时间算等于用了未来信息 |
| **一家一票** | 同机构同日同品种发多篇，取最新一篇 | 防止发得勤的机构主导指标 |
| **NA ≠ 0** | 某品种当日无覆盖 → 不产生记录，绝不写 0 | 0 意味着「有多有空、净额为零」，NA 意味着「没有信息」，含义相反 |
| **热度与方向分离** | `coverage_count` 独立成列 | 3 家看多和 30 家看多不该同权 |
| **双版本号** | `score.model_version` / `daily_index.calc_version` | 打分只追加不修改；改聚合口径可重算，不用重跑打分 |
| **baseline 对照** | 并排显示「只数家数」的净得分 | 复杂模型必须能跑赢最笨的办法，否则复杂度没换来价值 |

净得分公式：

```
net_score = (看多数 − 看空数) / 总数 × 100      # −100 ~ +100
大盘 0–100 分 = (net_score + 100) / 2
方向判定：direction > 0.25 记多，< −0.25 记空，其余中性
```

## 六、⚠️ Demo 与生产版的差异

**这是 demo，不是生产系统。**差异全部列在这里，没有隐藏：

| 环节 | 生产版设计 | demo 实现 | 原因 |
|---|---|---|---|
| 采集 | 官网适配器 + 邮件 IMAP 订阅 | `data/inbox/` 本地样本 | demo 不该依赖外网和反爬 |
| 解析 | MinerU（版面还原 + 表格） | txt 直通，PDF 留适配位 | MinerU 要装 torch 和几 GB 模型 |
| 打分 | 规则 → LLM → 人工三层漏斗 | **只有规则层** | 不能联网、不能装 SDK |
| 存储 | PostgreSQL | SQLite | 零配置；表结构 1:1 对齐 |
| 看板 | React + ECharts | 自包含 HTML（手写 SVG） | 不用装东西就能看 |
| 时点 | 调度器传入真实抓取时刻 | 由文件名回填 `publish_time + 06:30` | 否则 27 篇会落在同一秒，出不来时间序列 |

### 已知局限（诚实列出）

1. **规则命中率 99.6% 是偏高的。** 样本数据是照着规则表写的，真实研报表述五花八门，
   预期命中率 60–70%，剩下的要靠 LLM 兜底——即三层漏斗的第二层，demo 没实现。
2. **baseline 85.0 vs 本模型 65.5，不构成「谁更好」。** 两个数只是同一天的两种聚合口径，
   没有前瞻收益就无法判优劣。要证明模型有增量，需按 [01-开源项目技术调研.md](01-开源项目技术调研.md)
   第 3.3 节做中性化检验——demo 没有历史行情数据，做不了。
3. **负面非对称加权（`config.BEAR_WEIGHT`）已接好但默认 1.0（等权）。**
   分析师不轻易喊空，理论上负面该加权，但 demo 没有可用来定标该系数的历史数据，
   凭空拍一个 1.3 上去是假精确。留了开关，等有真实数据再定标。
4. **`daily_index` 表没有 `model_version` 列。** 换打分口径重跑聚合会覆盖旧口径的指标行。
   生产版应把它纳入主键，以便新旧口径并排对比。
5. **样本数据全部为虚构。** `data/inbox/` 下的研报是为演示编写的假数据，
   机构名虽为真实公司，内容与观点均与其真实研究结论无关，不构成任何投资建议。

## 七、下一步

demo 自身的迭代路线单独成文：**[05-Demo迭代Roadmap.md](05-Demo迭代Roadmap.md)**。

它和[架构方案第十节](03-架构方案.md#十-分阶段落地)那份 `MVP → v1 → v2` 不是一回事——
后者是**生产版**路线（假设有真实数据源、API 预算、真实用户），前者是**演示版**路线
（在离线、零依赖、一键跑通的约束下，尽可能把架构方案里的判断证明出来）。
两者的取舍标准不同，因此分开维护。

概要：

| 阶段 | 主题 | 补的缺口 |
|---|---|---|
| R0 | 文档与代码对齐 + 看板挂 GitHub Pages | 文档比代码旧 |
| R1 | 漏斗第 2 层：LLM 兜底（默认 fixture 回放，保持零依赖） | 全链路 0 次模型调用 |
| R2 | 难例集 + 规则 vs LLM 三方评测 | 没有「模型好不好」的量化证据 |
| R3 | 漏斗第 3 层：人工复核回流 | 数据飞轮只在文档里 |
| R4 | 有效性验证方案（纯文档，不写代码） | 数据不支持真跑回测，硬做即造假 |

明确**不做**：真实爬虫 / 邮件订阅、Streamlit 看板、真跑回测、微调模型。理由见 roadmap 第八节。
